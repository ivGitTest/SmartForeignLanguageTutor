# MVP — пакет на согласование

**Версия пакета:** 0.1  
**Дата:** 13 октября 2026  
**Статус:** НА СОГЛАСОВАНИИ. Реализация MVP не начата.  
**Подготовка:** Replit Agent. **Согласование:** владелец продукта.

Пользователь проверил прототип и сообщил: «в целом всё устраивает». Это разрешение готовить документацию MVP, не утверждение о прохождении всех формальных метрик качества.

## Документы

1. [Функциональные требования](functional-requirements.md) — возможности, правила данных, состояния и критерии приёмки.
2. [Требования к безопасности](security-requirements.md) — защита пользовательских ключей, приватность, расходы и проверки перед выпуском.
3. [Требования к дизайну экранов](screen-design-requirements.md) — навигация, состав экранов, состояния и требования к Figma.
4. [Архитектурная справка](architecture.md) — приложение без собственного сервера, компоненты, локальные данные и внешние API.

Основание: [общий черновик](../business-functional-requirements-draft.md) и [ТЗ прототипа](../prototype-technical-requirements.md). Прототип остаётся отдельным веб-инструментом; его сервер, ключ и ограничение одним владельцем не переносятся в мобильный MVP.

## Что прямо подтвердил пользователь

- Android-приложение; публичная аудитория зарегистрированных пользователей.
- Собственные пользовательские ключи и оплата; OpenRouter — единственный провайдер MVP.
- Два ограниченных списка моделей: А и Б.
- Предпочтение MVP без собственного сервера.
- Настройка родного языка, русский по умолчанию, перевод после улучшения, свёрнутый по умолчанию.
- Функции с пометкой MVP из исходного черновика; SQLite и Figma.
- Неизменность существенного смысла.

Остальные уточнения пакета — предложения для согласования. Статус всего пакета остаётся черновым до решения владельца.

## Решения, которые нужно согласовать

| ID | Вопрос | Предлагаемое решение | Влияние |
|---|---|---|---|
| D-01 | Где зарегистрирован пользователь? | Только в OpenRouter; отдельного аккаунта приложения нет. Локальные функции доступны без ключа, ИИ — с действующим ключом. | Прямые запросы не требуют нашего сервера. Если нужен отдельный аккаунт приложения, потребуется отдельно согласовать готовый сервис идентификации. |
| D-02 | Таймаут | 60 секунд на каждый сетевой запрос вместо исходных 10; настройку произвольного таймаута отложить. | Цепочка А → Б → перевод может занять до трёх отдельных таймаутов. |
| D-03 | Языки | Интерфейс EN/RU, по умолчанию EN; родной RU/EN/DE/FR/ES, по умолчанию RU; обучение EN. | Список родных языков — предложение, не уже реализованная возможность. |
| D-04 | Уровни | Текущий A1–C2; целевой выше текущего. При текущем C2 улучшение до более высокого уровня недоступно. | Прототип проверял только B1→B2/C1; другие пары требуют проверки. |
| D-05 | Хранение | SQLite и аудио в приватном хранилище приложения; без облачной синхронизации и автоматических резервных копий. | Удаление приложения/данных может привести к потере материалов; общей папки в файловом менеджере нет. |
| D-06 | Управление ИИ | Сохранить редактор инструкции Б и совместимых параметров; перевод выполняется отдельной инструкцией. | Пользовательская инструкция Б не должна случайно отключать перевод. |
| D-07 | Ограниченные списки | Три кандидата STT и три текстовых, перечисленные в архитектуре. Defaults — Whisper Large V3 и GPT-4.1 Mini. | Итоговый выпускной список содержит только модели, прошедшие реальную проверку; произвольного ввода ID нет. |
| D-08 | Граница MVP | Экспорт CSV/Anki, FSRS, выбор каталога, размер сессии и принудительные темы отложить. | Сохранён весь набор функций с явной пометкой MVP; неоднозначные пункты экспорта не добавлены автоматически. |
| D-09 | Обработка и история | 120 секунд / 10 MiB на запись; один последний результат Б на каждый целевой уровень для каждой записи; история повторных генераций не входит. | Журнал хранит много записей; заменять старые записи при новой больше не нужно. |

D-01 — обязательное уточнение перед финализацией: аккаунт OpenRouter нельзя незаметно назвать аккаунтом нашего приложения. Остальные предложения можно принять вместе с пакетом либо перечислить исключения.

## Что означает согласование

1. Зафиксирован состав MVP, значения по умолчанию и исключения.
2. Согласованы решения D-01…D-09 либо их исправленные варианты.
3. Можно переходить к макетам Figma, но не считать их заранее утверждёнными.
4. Реализация — только после согласования требований и экранов.
