# Архитектурная справка MVP

**Версия:** 0.3 · **Дата:** 13 октября 2026

**Статус:** СОГЛАСОВАНО пользователем без исключений.

**Тип:** архитектурное предложение, не описание уже реализованного мобильного приложения.

**Термины:** [единый словарь](../terminology.md).

## 1. Рекомендуемая архитектура

Нативный Android-клиент с локальными данными и прямым обращением к OpenRouter. Свой backend, API gateway, серверная БД и общий ключ для MVP не нужны.

```text
Android 13+ / приложение
  Режимы Словарь (старт), Материалы, Обучение; настройки
         │
  Независимые сценарии: аудио → А → Б → Перевод; карточки; SM-2
         │
  Доменные сущности / валидация / снимки настроек
         │
  ├── SQLite: записи, тексты, карточки, прогресс, обычные настройки
  ├── Приватные файлы: аудио и временные файлы
  ├── SecureStore / Android Keystore: только пользовательский ключ
  ├── Микрофон, плеер, системный TTS
  └── Адаптер OpenRouter + ограниченный каталог моделей
                 │
                 │ HTTPS; Authorization только из SecureStore
                 ▼
             OpenRouter
                 │
                 ▼
       Обслуживающий провайдер выбранной модели
```

«Без собственного сервера» не означает офлайн-ИИ или отсутствие внешних серверов: аудио/текст передаются OpenRouter и исполнителю модели.

## 2. Никакой регистрации и авторизации MVP

По прямому решению пользователя отсутствуют собственные аккаунты, user ID, пароли, экран входа, сессии, OIDC/OAuth/PKCE и app lock. Доступ к телефону/приложению пользователь защищает средствами ОС. Ключ OpenRouter вводится вручную и используется только для API; его проверка не является авторизацией пользователя в приложении.

Данные принадлежат локальной установке приложения, без идентификатора серверного аккаунта. Многопрофильность, синхронизация и внешний сервис идентификации в MVP не закладываются как обязательные зависимости. Встроенный вход веб-прототипа остаётся только в прототипе.

## 3. Технологии — предложение

| Область | Решение | Причина |
|---|---|---|
| Язык | TypeScript | Уже используется в проекте; доменную логику удобно тестировать отдельно от UI. |
| Мобильная платформа | React Native + Expo, существующий `artifacts/mobile-app` | Нативные API и существующий шаблон; SDK сейчас 57, обновление версии отдельно не требуется. |
| Навигация | Expo Router | Уже подключён; экраны разделяются по пользовательским сценариям. |
| Учебные данные | `expo-sqlite` | SQLite, транзакции, текущие артефакты, журнал материалов и сохранённые учебные сессии. |
| Секрет | `expo-secure-store` | Android Keystore-backed шифрование; не общий ключ в bundle. |
| Аудио | `expo-audio` | Запись/плеер через нативные API; подтвердить выбранный codec на реальном устройстве. |
| Файлы | `expo-file-system` | Приватные документы и удаление временных файлов. |
| Озвучивание | `expo-speech` / системный TTS | Без ещё одной платной модели и без передачи ключа. Офлайн зависит от установленного голоса. |
| Сеть | Стандартный `fetch`, AbortController, нормализованный адаптер | Небольшое число endpoints; не требуется собственный SDK/серверный прокси. |
| Валидация | Zod | Уже есть в проекте; строгие настройки/ответы. |
| Планировщик | Поддерживаемая реализация SM-2, изолированный адаптер | Выбор библиотеки/лицензии подтвердить при техподготовке; FSRS интерфейсом не смешивать. |
| Дизайн | Figma, нативные Android-компоненты | До реализации согласовать экраны и состояния. |

Это перечень для будущей реализации, не утверждение об установке перечисленных пакетов. Совместимость зависит от текущего Expo SDK; пакеты подключать через штатный Expo-механизм. Минимальную Android 13 задавать в нативной release-конфигурации, а не только в описании приложения.

## 4. Разделение ответственности

- UI: три независимых режима, старт со Словаря; одна светлая тема, без ключа в общем state.
- Сценарии: отдельные А и Б, автоматический Перевод после Б; отмена, снимок настроек, сохранение каждого успеха.
- Домен: CEFR, признаки устаревания, карточки и расписание SM-2; без зависимости от React или HTTP.
- Репозитории: SQLite, файлы, защищённое хранилище.
- OpenRouter adapter: фиксированный origin, форматы запросов, чтение ключа, валидация ответа, ошибки.
- ModelCatalog: ограниченные ID и подтверждённые возможности; не произвольный список из внешнего API.

Не нужен микросервисный подход, очередь на сервере или серверная PostgreSQL. Код прототипа использовать только как источник проверенных правил/инструкций; browser MediaRecorder/IndexedDB и серверный Replit Auth не переносить в Android механически.

## 5. Локальная модель данных

Предложенные сущности, не окончательная SQL-схема:

| Сущность | Основные данные |
|---|---|
| Material | UUID, дата, заголовок/превью, состояние единственной текущей цепочки аудио/А/Б/Перевода. |
| Recording | Локальный UUID, createdAt UTC, длительность, приватный путь, MIME/codec, размер, наличие аудио. |
| Transcript | materialId, одна редактируемая А, редакция, происхождение «STT/ручная правка», модель/параметры/время распознавания. Отдельного неизменяемого А нет. |
| ImprovedText | materialId, единственная текущая Б, целевой уровень, редакция А, снимок её текста/настроек, состояние complete/incomplete/stale. Нет параллельной Б для каждого уровня. |
| Translation | Единственная текущая связь с Б и её редакцией, язык, текст, модель/промпт/время; не флаг раскрытия UI. |
| VocabularyCard | Выражение, перевод, языковая пара, пример, ссылка на источник, normalizedExpression. |
| ReviewState | cardId, repetitions, interval, EF, dueAt UTC, timezone расчёта, lastReviewedAt. |
| ReviewEvent | cardId, sessionId, уникальный eventId, оценка, дата; для идемпотентности и восстановления. |
| LearningSession | Фиксированные ID до 10 карточек, языковая пара на старте, позиция, сторона/раскрытие, очередь повторов, оценки, состояние active/paused/complete. Новые слова не подмешиваются. |
| Settings | Model IDs, отдельные промпты, совместимые параметры, версия defaults и подтверждение передачи данных. Языки EN/RU/EN и B1 → B2 — фиксированная конфигурация MVP, не пользовательские настройки. |
| NavigationState | Последний materialId, положение/фильтры списков и ссылка на активную сессию. При холодном старте всегда режим Словарь, а не сохранённый режим. |

**Ключа, Authorization и секретных tokens в этих сущностях нет.** Никакой таблицы аккаунтов приложения. Уникальность А/Б/Перевода обеспечивается по materialId, а не по паре materialId+CEFR. Снимок А внутри Б — данные для происхождения/актуальности, не отдельный пользовательский артефакт или история генераций.

Конфигурация MVP: интерфейс `en`, родной `ru`, обучение `en`, исходный CEFR `B1`, целевой `B2`. Она не зависит от локали ОС и не изменяется резетом. Для Б передавать B1/B2, для Перевода и контекстного перевода — EN → RU. Языковые коды и уровень сохранять в данных происхождения для будущего развития; многозначных селекторов и сценариев смены языка/уровня в MVP нет.

Индексы: дата записей, ссылка текста на запись, пара языков/поиск словаря, срок повторения. SQLite migrations версионированы и транзакционны; обновление не стирает записи. При необратимом сбое не делать автоматический reset БД.

## 6. Согласованность и жизненный цикл

1. Запись во временный приватный файл → закрыть recorder → проверить размер/длительность → переместить в постоянное хранилище → транзакция метаданных. При сбое убрать только незавершённый файл.
2. А создаётся только из аудио по отдельному действию. Б создаётся только из сохранённой А по отдельному действию. Успех новой Б атомарно заменяет прежнюю Б и удаляет связь со старым Переводом; следующий Перевод сохраняется отдельно. Его ошибка не отменяет новую Б.
3. Ключ хранится и заменяется SecureStore отдельно от SQLite; не копируется в снимок настроек.
4. Снимок параметров фиксируется при старте цепочки; новая настройка не влияет на уже отправленный запрос.
5. Уникальный operationId и редакция входа защищают от поздних ответов. Только активная операция с соответствующим входом может сохранить результат.
6. Удаление данных отменяет связанную операцию; поздний ответ не создаёт удалённую запись заново.
7. Удаление аудио/текста/карточки — разные транзакции и явные пользовательские решения. Карточки сохраняют свой контекст независимо от источника.
8. Временные/сиротские файлы проверяются при запуске; существующие сохранённые записи не удаляются ради освобождения места.
9. Правки А, состояние материала и оценка/позиция сессии сохраняются локально при изменении, не только при выходе из режима. Переключение режимов не уничтожает их store/repository state.
10. Новая карточка добавляется в словарь, но ID текущей сессии и её очередь неизменны. При завершении/«Продолжить» создать новую сессию из актуального словаря; при удалении карточки пропустить её, не вставлять новую.
11. Резет применяет текущую версию defaults настроек/промптов; не выполняет truncate БД и не удаляет SecureStore. Результаты с прежними настройками сохраняются с корректным снимком/признаком устаревания.

## 7. Контракты внешних API

| Операция | Endpoint | Данные |
|---|---|---|
| Проверка каталога | GET `/api/v1/models?output_modalities=transcription` и GET `/api/v1/models` | Пересечение с allowlist; публичные данные, не повод отправлять ключ. |
| А | POST `/api/v1/audio/transcriptions` | Model ID, audio, language `en`, response_format `json`; temperature только после проверки поддержки. |
| Б | POST `/api/v1/chat/completions` | System = текущий пользовательский промпт Б; user = только А и фиксированные B1/B2 как данные; поддерживаемые параметры. |
| Перевод | POST `/api/v1/chat/completions` | Текущий промпт Перевода, только Б как данные, родной язык; модель из снимка Б. |
| Контекстный перевод | POST `/api/v1/chat/completions` | Текущий промпт, выделение и короткий контекст, родной язык; один наиболее очевидный контекстный эквивалент. |

База всех путей — `https://openrouter.ai`, HTTPS. Проверка ключа через документированный read-only endpoint уточняется при реализации; не использовать платную генерацию как скрытую проверку.

### Аудио

Документация STT подтверждает base64 JSON и OpenAI-совместимый multipart с лимитом 25 MB. Для MVP предложен multipart, чтобы избежать копии base64 в памяти. Локальный предел 10 MiB меньше лимита провайдера.

Нативный исходный кандидат формата — M4A/AAC. Перед фиксацией каждой модели подтвердить этот формат на Android 13/14. Если модель не принимает его, согласовать общий формат/конвертацию либо убрать модель из списка; не маскировать преобразование расширением файла. Потоковое STT и длинные записи не включены.

### Промпт А и достоверность настройки

OpenRouter STT документирует, что общее поле `prompt` в multipart принимается, но игнорируется. Поэтому нельзя просто добавить редактор и заявить, что он влияет на А. Для каждого кандидата проверить provider-specific vocabulary/prompt options и допустимость их маршрутизации. Редактор А доступен только при фактической поддержке; иначе явно сообщить ограничение и не отправлять бесполезное поле. Б, Перевод и контекстный перевод всегда имеют видимые редактируемые промпты по SET-09.

### Тарифы

Сохранять публичный тариф вместе с его единицей, источником и временем проверки. Для текстовых моделей преобразовывать USD/token в USD/1 млн токенов отдельно для входа/выхода; справочное среднее — их полусумма, не прогноз расхода. Для STT по длительности — USD/мин после подтверждения единицы провайдера. Нельзя применять коэффициент 1 млн к тарифу за секунду или выдавать минимальную цену endpoint за достоверную среднюю по всем исполнителям. Нет данных — явное отсутствие тарифа.

### Текстовые ответы

Не исполнять tools и содержимое ответа. Для Б нужен текст; переводы/карточка могут использовать подтверждённый structured output с валидацией схемы. При невалидном ответе показать ошибку, без автоматического второго платного «repair» запроса. `finish_reason=length` означает incomplete.

Параметры отправляются только по матрице подтверждённой поддержки. Для text endpoints использовать `provider.require_parameters=true`, если это подтверждено актуальным контрактом; несовместимость — ошибка, не скрытое удаление параметра. STT не считать автоматически совместимым с этим механизмом.

## 8. Ограниченные списки моделей — кандидаты D-07

На дату подготовки ID и соответствующие modalities проверены через публичный Models API OpenRouter. **Реальные платные вызовы в этом этапе не выполнялись.** Форматы, параметры, дословность, перевод и соответствие CEFR ещё должны пройти проверку.

### Распознавание А

| Model ID | Предлагаемая роль | Ограничение |
|---|---|---|
| `openai/whisper-large-v3` | Default; преемственность с прототипом | Проверить сохранение ошибок/повторов и M4A. |
| `openai/whisper-large-v3-turbo` | Альтернативный STT-кандидат | Скорость/цена и дословность измеряются, не обещаются названием. |
| `openai/gpt-4o-mini-transcribe` | Альтернативная ASR-модель | Возможна нормализация речи; параметры STT подтвердить отдельно. |

### Улучшение Б и переводы

| Model ID | Предлагаемая роль | Ограничение |
|---|---|---|
| `openai/gpt-4.1-mini` | Default; преемственность с прототипом | Проверить улучшение B1 → B2, Перевод/контекстный перевод EN → RU и параметры. |
| `google/gemini-2.5-flash` | Альтернативная текстовая модель | Особенности reasoning/параметров не включать без необходимости. |
| `openai/gpt-4.1` | Дополнительный кандидат | Более дорогая модель не считается автоматически лучшей. |

Каталог встроен в приложение и версионируется с релизом. Сетевое обновление показывает доступность/тариф, но не добавляет произвольные модели. Нет `auto`, «любая бесплатная» или silent fallback. Недоступный выбранный ID остаётся видимым с ошибкой и предложением ручной замены.

Цена зависит от модели и исполнителя; не фиксировать маркетинговое «бесплатно». Наличие ID в каталоге не гарантирует доступность конкретному аккаунту, региону или endpoint. Перед выпуском каталог проверить повторно.

## 9. Расширяемость без преждевременной реализации

- Отдельный интерфейс AIProvider позволяет позже добавить провайдера, но HuggingFace сейчас не реализуется.
- Scheduler отделён от карточки; FSRS можно добавить миграцией после отдельного согласования.
- Данные UUID/редакции допускают будущий sync, но серверного протокола и конфликтов sync в MVP нет.
- Сохранять языковые коды и происхождение перевода для дополнительных языков.
- Экспорт/SAF хранить как будущие сценарии репозиториев; никаких публичных файлов с ключом.

## 10. Проверки и риски перед реализацией

1. Остальные технические предложения согласованы; отсутствие регистрации/авторизации уже прямо указано пользователем.
2. Native SecureStore, backup rules, recorder, multipart и TTS проверены на Android, не только в web/Expo Go.
3. Поддерживаемая SM-2 библиотека/лицензия и timezone-правила выбраны.
4. Для каждой модели подтверждены транспорт, формат, параметры и качество; не сравнивать исключительно по описанию провайдера.
5. Предусмотрены ошибки SQLite/файлов и восстановление без удаления данных.
6. Проверки release APK/AAB и приватности до публичной передачи пользователям.
7. Три сценария AC-18…AC-20 и восстановление позиции/стороны сессии проверены после переключения/закрытия приложения.

Основные риски: ограничения API по аккаунту/региону, изменение каталога, STT-нормализация ошибок, искажение смысла Б/перевода, утрата локальных данных, компрометация телефона. Отсутствие своего сервера снижает инфраструктурную сложность, но не устраняет эти риски.
