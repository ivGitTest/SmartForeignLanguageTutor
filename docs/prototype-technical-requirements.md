# Технические требования к прототипу приложения для изучения английского

**Версия:** 0.1  
**Дата:** 12 октября 2026  
**Статус:** НА СОГЛАСОВАНИИ — не разрешение на реализацию  
**Согласующий:** владелец продукта  
**Основание:** исходный черновик требований и два раунда уточнений.

## 1. Назначение и решение по итогам прототипа

Проверить цепочку «английская речь пользователя → исходный английский текст → естественная формулировка той же мысли на целевом уровне CEFR».

Прототип проверяет две гипотезы:
1. Распознавание достаточно точно передаёт речь изучающего язык, включая акцент и грамматические ошибки.
2. Переформулирование улучшает язык, но не изменяет существенный смысл, факты и намерение.

Результат этапа: работающий инструмент проверки, контрольные результаты, перечень дефектов и решение — продолжать выбранную связку, изменить инструкцию/модель либо пересмотреть подход.

Техническая готовность прототипа и положительный результат проверки гипотез — разные результаты. Неудовлетворительное качество ИИ должно быть зафиксировано, а не скрыто ради перехода к MVP.

## 2. Статус решений

### 2.1. Прямо подтверждено пользователем

| Область | Решение |
|---|---|
| Формат прототипа | Простой веб-интерфейс из исходного черновика |
| Устройство проверки | Смартфон Android 14 |
| Язык исходной речи | Английский |
| Говорящие | Один человек |
| Сценарии | Повседневная речь; ответы на вопросы интервью/собеседования |
| Уровни проверки | B1 → B2 и B1 → C1 |
| Смысл | Искажать нельзя |
| Связка ИИ | Одна связка, без интерфейса сравнения нескольких моделей |
| Провайдер | OpenRouter |
| API-ключ | На сервере, не вводится в интерфейсе прототипа |
| Текст А | Стремимся сохранить ошибки, повторы и слова-паразиты; пунктуация допустима |
| Хранение | Последняя запись и тексты переживают обновление страницы до следующей записи |
| Figma | Начиная с MVP; макеты прототипа в Figma не нужны |
| Процесс | Уточнение → согласование → реализация → проверка/исправления |

### 2.2. Предложения, требующие согласования вместе с этим документом

- Chrome на Android 14 как основной поддерживаемый браузер.
- Русский интерфейс; английский для обоих результатов.
- Максимальная запись 120 секунд; максимум аудиофайла 10 MiB.
- Таймаут каждой операции API — 60 секунд, включая загрузку на сервер.
- Возможность исправить текст А перед операцией Б.
- Сохранение последней пары результатов B2/C1: по одному актуальному результату на уровень, без истории генераций.
- Модели: `openai/whisper-large-v3` и `openai/gpt-4.1-mini`.
- Защита доступа: вход через Clerk и серверное разрешение платных запросов только одному владельцу.
- Контрольный набор и пороги качества из раздела 12.

Неотвеченные предложения из предыдущего сообщения не считаются автоматически принятыми. Согласование этого документа означает принятие перечисленных здесь значений, если пользователь не указал исключения.

## 3. Объём работ и исключения

### Входит

- Настройки исходного и целевого CEFR.
- Запись микрофона, остановка, отмена текущей записи и прослушивание.
- А: распознавание речи.
- Просмотр оригинального результата А и отдельного редактируемого текста для Б.
- Б: переформулирование в B2 или C1.
- Повторная операция Б без повторной отправки аудио.
- Локальное сохранение последней завершённой записи, результатов и настроек.
- Удаление локальной записи и текстов по явному действию.
- Ошибки, ожидание, отмена запроса и явный повтор.
- Отображение моделей и измеренного времени обработки.
- Минимальный контроль доступа к серверному ключу — отдельное предложение на согласование.

### Не входит

- Нативная реализация и установка APK; изменение существующего Expo-шаблона.
- Словарь, переводы слов, карточки, SM-2/FSRS, Anki и CSV-экспорт.
- История аудио и текстов, облачная синхронизация, резервные копии.
- Озвучивание текстов; аудиофайлы прослушивать можно.
- Диалог с ИИ, генерация вопросов интервью, определение говорящих.
- Оценка произношения, автоматическая диагностика реального CEFR пользователя.
- Выбор нескольких провайдеров, произвольный ввод модели, сравнение моделей.
- Потоковое распознавание, работа ИИ офлайн, продолжение записи в фоне.
- Публичная регистрация как продуктовая функция, роли, профиль пользователя.
- Полный визуальный дизайн в Figma.

## 4. Архитектура и технологии

```text
Chrome / Android 14
  React + TypeScript + Vite
  MediaRecorder / getUserMedia — микрофон
  IndexedDB — последняя запись, тексты, настройки
  Clerk — подтверждение личности владельца [предложение]
           |
           | HTTPS, JSON / multipart/form-data
           v
Существующий API-сервер проекта
  Node.js + TypeScript + Express
  Проверка доступа, входных данных, лимитов
  Адаптер OpenRouter, серверные инструкции обработки
           |
           | HTTPS + серверный API-ключ
           v
OpenRouter
  Speech-to-text: openai/whisper-large-v3
  Text generation: openai/gpt-4.1-mini
```

1. Веб-прототип — отдельный frontend в этом же проекте, предлагаемый каталог `artifacts/language-prototype`.
2. Предлагаемый адрес интерфейса: `/language-prototype/`. Все браузерные URL и API-вызовы учитывают этот префикс.
3. API реализуется в существующем сервере, без второго сервера и без замены существующей инфраструктуры.
4. Предлагаемый публичный префикс API: `/language-prototype/api/v1`. При реализации требуется зарегистрировать его в маршрутизации проекта и в Express.
5. Контракт API описывается в OpenAPI до реализации; клиент и схемы проверки генерируются принятым в проекте способом.
6. Сервер не хранит пользовательские аудио и тексты в постоянной БД. Существующая PostgreSQL не используется для них.
7. SQLite из исходного черновика остаётся требованием к будущему мобильному решению и пересматривается на этапе MVP, не заменяется IndexedDB для всего продукта.
8. Распознавание и переформулирование разделены адаптером. Возможность заменить провайдера закладывается интерфейсом, но адаптер Hugging Face сейчас не реализуется.
9. Рабочая доступность выбранных моделей, форматов и аккаунта подтверждается реальными запросами при реализации. Документация провайдера не заменяет эту проверку.

## 5. Интерфейс и настройки

Одна основная рабочая страница и панель настроек. При принятии защиты доступа также нужен экран входа.

### Рабочая страница

- Состояние записи, таймер, кнопки «Записать», «Остановить», «Отменить запись».
- Прослушивание последнего завершённого аудио.
- Кнопка «А — распознать».
- Неизменяемый исходный результат А.
- Редактируемая копия «Текст для улучшения» и действие сброса к оригиналу А.
- Выбор целевого уровня B2/C1, кнопка «Б — улучшить».
- Оригинал и результат Б доступны для сравнения без потери одного из них.
- При переключении B2/C1 показывается сохранённый результат этого уровня, если он есть и актуален.
- Действие «Удалить запись и результаты» с подтверждением.
- Модель, время обработки, статус и ошибка соответствующей операции.

На узком экране текстовые блоки расположены последовательно; таблица в две колонки не обязательна. Кнопки доступны для касания, длинные тексты не обрезаются. Текст можно выделять и копировать стандартными средствами браузера.

### Настройки

| Поле | Значение и поведение |
|---|---|
| Исходный CEFR | A1–C2, по умолчанию B1; контрольная оценка только при B1 |
| Целевой CEFR | B2 или C1, по умолчанию B2; должен быть выше исходного |
| Провайдер и модели | Только просмотр; фиксируются на сервере |
| Ключ доступа | Отсутствует в интерфейсе |
| Ограничения | Показать максимум записи и срок ожидания; не редактируются |
| Язык интерфейса | Русский, без переключателя |
| Тема | Системная; ручной выбор не входит |

При исходном уровне B2 доступен только целевой C1. При C1/C2 допустимых целевых уровней прототипа нет: показать объяснение и запретить Б. А остаётся доступной.

## 6. Запись и жизненный цикл данных

### REC-01. Разрешение микрофона

- Запрашивается только по действию «Записать», не при открытии страницы.
- Нужен HTTPS. Отказ, отсутствие микрофона и неподдерживаемый браузер обрабатываются отдельными сообщениями.
- Запись не отправляется внешним сервисам автоматически.
- Перед первым платным запросом пользователь видит уведомление о передаче аудио/текста OpenRouter и обслуживающему провайдеру.

### REC-02. Запись

- Один аудиопоток, без определения говорящих.
- Формат выбирается через проверку поддержки MediaRecorder, предпочтительно WebM/Opus.
- При достижении 120 секунд запись автоматически останавливается.
- Остановка микрофона освобождает все media tracks.
- Запись в фоне и при заблокированном экране не гарантируется. Если браузер прерывает запись, показываем это явно и сохраняем доступный завершённый фрагмент, если он корректен.
- При обновлении страницы незавершённая запись может быть потеряна; последняя успешно сохранённая остаётся.

### REC-03. Замена последней записи

- Перед новой записью предупреждаем, что завершение новой записи заменит предыдущую и её результаты.
- Старую запись не удаляем при простом нажатии «Записать».
- Новое аудио и сброс связанных результатов сохраняются одной транзакцией IndexedDB только после успешного завершения и проверки непустого файла.
- Отмена, отказ микрофона, пустая запись или ошибка хранения не должны молча уничтожить старую запись.
- Во время платного запроса начать новую запись нельзя; сначала нужно закончить или отменить запрос.

### DATA-01. Локальная структура

- Settings: версия схемы, исходный/целевой CEFR.
- Recording: случайный идентификатор, дата/время ISO 8601, Blob, MIME-тип, длительность.
- TranscriptA: исходный текст распознавания, модель, дата, время запроса.
- EditableText: текст для Б и номер его редакции.
- ResultsB: максимум один результат B2 и один C1; каждый связан с записью, редакцией текста, исходным уровнем, моделью и версией инструкции.
- Никаких API-ключей в этих данных.

### DATA-02. Восстановление и актуальность

- После обновления страницы восстанавливаются аудио, результаты и настройки; микрофон автоматически не включается.
- Изменение текста для Б или исходного CEFR делает прежние результаты Б неактуальными; нельзя показывать их как результат новой редакции.
- Поздний ответ отменённого/устаревшего запроса не может перезаписать текущие данные.
- Чувствительные локальные данные очищаются при выходе владельца; повторное использование требует нового входа.
- Отдельное удаление очищает аудио и тексты, но сохраняет настройки.
- Если IndexedDB недоступна или заполнена, показываем ошибку. Не выдаём режим только в памяти за успешное постоянное сохранение.
- Хранение ограничено браузером и устройством: очистка данных сайта, приватный режим и вытеснение браузером могут удалить данные. Это явно указано пользователю; гарантия резервного хранения отсутствует.

## 7. Операция А — распознавание

### ASR-01

- А доступна после появления завершённого аудио.
- Сервер отправляет аудио в `/api/v1/audio/transcriptions` OpenRouter с английским языком и фиксированной моделью.
- Сервер проверяет размер, реальный формат и длительность, а не только значения из браузера. Для анализа контейнера использовать стандартные ffprobe/ffmpeg; конвертировать только при необходимости совместимости.
- Временные файлы, если нужны, удаляются после успеха, ошибки или отмены; аварийные остатки очищаются по сроку хранения не более 15 минут.
- Цель — дословная речь с ошибками, повторами и словами-паразитами. Пунктуация и регистр допустимы.
- Дополнительная языковая модель для «очистки» А не используется.
- Не обещаем, что ASR всегда сохранит ошибки и повторы: склонность выбранной модели нормализовать речь проверяется отдельно.
- Пустой ответ и ответ на тишину не принимаются автоматически за успешное распознавание.
- Исходный ответ А сохраняется отдельно; его нельзя перезаписывать ручными правками.

### ASR-02. Повтор

Явный повтор А является новым платным запросом. Если уже есть правки/Б, предупредить об их сбросе после успешного нового распознавания. Ошибка повторного А сохраняет предыдущие данные.

## 8. Операция Б — переформулирование

### REW-01. Вход

- Используется текущий «Текст для улучшения», не исходное аудио.
- Б запрещена без непустого текста А/его отредактированной копии.
- Предлагаемый предел текста — 10 000 символов.
- Текст, исходный CEFR и целевой CEFR передаются серверу; инструкцию и модель задаёт сервер.
- Б без выполненной А не запускается: интерфейс предлагает сначала А.

### REW-02. Правила инструкции

- Ответ только на английском, в форме переформулированного текста.
- Сохранить факты, имена, числа, даты, участников, причинные связи, время событий, отрицания, условия, обязательства и степень уверенности.
- Нельзя добавлять опыт, достижения, причины и детали, которых не было во входе.
- Исправлять грамматику, выбирать естественные выражения и конструкции целевого уровня.
- Не вставлять идиомы и фразовые глаголы искусственно только ради «сложности».
- Для B2 — естественная, более точная речь; для C1 — более гибкое и нюансированное выражение той же мысли.
- Сохранять разговорный характер исходного текста; не превращать повседневную речь в академическое эссе.
- Не сокращать существенное содержание и не расширять его новыми утверждениями.
- Если смысл неоднозначен или во входе отмечено неразборчивое место, не додумывать факты: сохранять неоднозначность/маркер. Если безопасное преобразование невозможно, вернуть понятный отказ обработки.
- Текст пользователя рассматривается как данные, а не инструкции для модели.

Версия серверной инструкции сохраняется вместе с результатом. Настройки генерации фиксируются и документируются; даже при низкой температуре идентичный ответ не гарантируется.

### REW-03. Результат

- Успешный ответ сохраняется только для соответствующей редакции входа и уровня.
- Повторная Б обновляет один результат выбранного уровня, без истории.
- Ошибка/отмена Б не уничтожает аудио, А и предыдущий успешный результат.
- Интерфейс не утверждает, что CEFR сертифицирован. Формулировка: «Вариант с ориентацией на B2/C1».
- Переводы, объяснения замен и учебные карточки в ответ Б не входят.

## 9. Контракт API

Префикс: `/language-prototype/api/v1`. Все запросы — same-origin по HTTPS. При согласовании защиты требуется проверенная сессия владельца.

| Метод и путь | Запрос | Успешный ответ |
|---|---|---|
| GET `/config` | Без тела | Провайдер, ID моделей, уровни, лимиты, версия инструкции, доступность серверной конфигурации; без секретов |
| POST `/transcriptions` | multipart: `audio`, `recordingId`, `requestId` | `recordingId`, `requestId`, `text`, `model`, `processingMs`, `createdAt`, `usageCostUsd` |
| POST `/rewrites` | JSON: `recordingId`, `requestId`, `textRevision`, `text`, `sourceLevel`, `targetLevel` | Те же идентификаторы/редакция, `text`, уровни, `model`, `promptVersion`, `processingMs`, `createdAt`, `usageCostUsd` |

- `usageCostUsd` — число или null: отображать стоимость только если провайдер её действительно вернул. Отсутствие не означает нулевую стоимость.
- `processingMs` — время обработки сервером; клиент отдельно измеряет общее ожидание с загрузкой.
- `recordingId`/`requestId` — идентификаторы корреляции, не авторизация и не облачные объекты.
- Произвольные модели, URL провайдера и инструкции с клиента не принимаются.
- Записи и результаты не сохраняются на сервере; GET истории и CRUD облачных записей не нужны.
- Формат ошибки: `{ error: { code, message, requestId, retryable } }`.
- Ошибки клиента: 400 — данные/уровни, 401 — нет входа, 403 — не владелец, 413 — файл слишком большой, 415 — неподдерживаемый формат.
- Служебные ошибки: 409 — запрос уже выполняется, 429 — лимит, 502 — некорректный ответ внешнего сервиса, 503 — сервис/конфигурация недоступны, 504 — таймаут.
- Ошибка авторизации/баланса внешнего провайдера не выдаётся за ошибку входа пользователя. Подробности и ключи внешнего запроса клиенту не раскрываются.

## 10. Ожидание, ошибки и ограничения расходов

- Состояния А/Б: не готова, готова, выполняется, завершена, ошибка, отменена.
- В интерфейсе одновременно выполняется одна операция.
- На сервере — один активный платный запрос владельца и максимум пять стартов платных запросов в минуту. Лимит проверяется до внешнего вызова.
- Кнопки не позволяют отправить запрос повторным касанием; сервер отдельно защищает от параллельных запросов.
- Автоматических повторов нет: повтор инициирует пользователь.
- Таймаут 60 секунд для одной операции — техническое ограничение, а не обещание SLA. А и Б запускаются отдельно.
- Отмена прерывает ожидание и по возможности внешний запрос. Провайдер мог уже обработать запрос и списать средства; отмена не гарантирует отсутствия оплаты.
- После обновления страницы запрос не запускается автоматически. Незавершённый запрос мог быть выполнен провайдером; показываем отсутствие сохранённого результата, а не предлагаем «бесплатный» повтор.
- При обрыве сети, 429/5xx, недостаточном балансе, пустом результате и таймауте показываем понятное сообщение с допустимым следующим действием.
- Ошибки не удаляют локальные данные.
- Точные расходы и жёсткий предел бюджета задаются у провайдера, если аккаунт это поддерживает. Rate limit приложения не является денежным лимитом.

## 11. Безопасность, приватность и качество интерфейса

### SEC-01. Серверный ключ

- Хранится через защищённое серверное хранилище секретов проекта.
- Не включается в frontend, переменные публичного frontend-префикса, Git, ответы API, URL, логи и тексты ошибок.
- `.env` и другие реальные секретные файлы исключаются из Git; пример конфигурации содержит только названия полей и пустые значения.
- Не запрашиваем ключ в чате и не сохраняем его в документации.

### SEC-02. Доступ владельца — предложение на согласование

- Использовать управляемую аутентификацию Clerk, без самостоятельной реализации паролей/JWT.
- Каждый endpoint прототипа проверяет сессию на сервере; платные операции дополнительно разрешены только заранее заданному ID владельца.
- Первому вошедшему пользователю права владельца автоматически не выдаются.
- Посторонний пользователь, даже имеющий аккаунт, не получает право вызывать OpenRouter.
- У прототипа нет продуктовых экранов регистрации/профиля и каталога пользователей. Настройка учётной записи владельца — часть подготовки среды.
- Не считать скрытые кнопки, неизвестный URL, CORS, наличие ссылки только у владельца или rate limit достаточной защитой ключа.
- Если этот вариант отклонён, перед реализацией нужно согласовать другую проверяемую защиту доступа. Общедоступный незащищённый платный API не реализуется.

### SEC-03. Аудио и текст

- На сервере не ведётся постоянный журнал содержимого речи.
- В логах допустимы код ошибки, операция, обезличенный requestId и время; запрещены тело аудио, расшифровка и токены.
- Внешний сервис получает только данные, необходимые для операции. Условия хранения и обработки у OpenRouter/обслуживающего провайдера проверяются перед подключением; локальное удаление не гарантирует удаления у внешнего сервиса.
- Запись не отправляется автоматически при восстановлении страницы.
- Результаты отображаются как текст, не как исполняемый HTML.
- Недоверенный текст не может менять модель, endpoint и системную инструкцию.
- Файлы с инструкциями агенту, не относящимися к поставке приложения, исключаются из Git согласно исходному черновику; проектные документы требований не содержат секретов.

### UI-01

- Удобный адаптивный интерфейс от ширины 360 CSS px, без горизонтального скролла страницы.
- Размер основных целей касания не менее 44 × 44 CSS px.
- Читаемый текст, подписи элементов, заметные состояния ошибок и недоступности.
- Светлая/тёмная системная тема; исходные и улучшенные тексты визуально различимы.
- Макеты Figma для этого этапа не создаются. Итоговый интерфейс прототипа не считается утверждённым дизайном MVP.

## 12. Приёмка и оценка ИИ

### 12.1. Техническая приёмка

Все обязательные сценарии ниже должны проходить на Android 14 / Chrome.

| ID | Given / When / Then |
|---|---|
| T01 | Нет разрешения микрофона → отказать в доступе → понятная ошибка, старая запись сохранена |
| T02 | Есть доступ → записать/остановить речь → аудио воспроизводится и сохранено |
| T03 | Есть старая запись → отменить новую → старая запись и тексты остаются |
| T04 | Есть старая запись → успешно завершить новую → старая заменена, её результаты сброшены |
| T05 | Есть аудио/тексты → обновить страницу → данные и настройки восстановлены, микрофон выключен |
| T06 | Есть аудио → выполнить А → оригинал А сохранён отдельно от редактируемой копии |
| T07 | Есть А → исправить копию и выполнить Б → улучшение основано на копии, исходный А не изменён |
| T08 | Есть результат B2 → выбрать C1 и выполнить Б → нового запроса распознавания нет |
| T09 | Есть Б → изменить входной текст/исходный CEFR → старый Б не показывается как актуальный |
| T10 | Запрос выполняется → повторно нажать/отменить/получить поздний ответ → нет параллельной обработки и перезаписи устаревшим ответом |
| T11 | Есть данные → сеть/провайдер недоступны или истёк таймаут → ошибка без потери данных и без автоповтора |
| T12 | Есть данные → удалить и обновить страницу → аудио/тексты отсутствуют, настройки сохранены |
| T13 | Запись достигла 120 секунд / файл превышает лимит → остановка/отказ до вызова провайдера |
| T14 | Хранение недоступно/переполнено → сообщение, нет ложного подтверждения сохранения |
| T15 | Нет входа или вошёл не владелец → прямой запрос API отклонён до платного внешнего вызова |
| T16 | Проверить bundle, сеть, ответы и логи → серверный ключ и содержимое речи не раскрыты |
| T17 | Есть только тишина/неразборчивая речь → выдуманный связный текст не принимается как достоверный результат |

Тесты API покрывают валидацию, лимиты, отсутствие доступа и ошибки провайдера. Измерения качества ИИ требуют реальных запросов; подменённые ответы не доказывают качество модели.

### 12.2. Контрольный набор

Предлагаются десять записей продолжительностью 20–90 секунд; каждая проверяется с B2 и C1. Шесть повседневных и четыре интервью. Перед записью фиксируется эталон фактически произнесённых слов и список существенных утверждений.

| № | Тема | Что проверяем |
|---|---|---|
| 1 | Рабочий день | Время и порядок событий |
| 2 | Покупки | Числа, количество, отрицания |
| 3 | Планы на выходные | Условия и неопределённость |
| 4 | Поездка | Прошедшее время, даты, места |
| 5 | Решение бытовой проблемы | Причина, действие, результат |
| 6 | Предпочтения | Сравнение, «обычно» и «всегда», повторы |
| 7 | Рассказ об опыте | Реальные сроки и обязанности; запрет придуманных достижений |
| 8 | Сложная рабочая ситуация | Кто что сделал и почему |
| 9 | Ошибка и извлечённый урок | Ответственность, причинные связи, отрицания |
| 10 | Планы профессионального развития | Намерение против обещания; степень уверенности |

Включить естественные для пользователя грамматические ошибки, слова-паразиты, самокоррекции, числа и имена. Не ограничивать оценку идеально прочитанными фразами. Не использовать реальные секреты или конфиденциальные данные.

### 12.3. Метрики и предлагаемые пороги

- **А, точность слов:** WER = (замены + удаления + вставки) / количество слов эталона. Для сравнения нормализуем регистр/пунктуацию и единообразное написание чисел; грамматические ошибки, повторы и слова-паразиты не удаляем из эталона.
- Предлагаемый ориентир: суммарный WER на контрольном наборе не выше 15%. Сохранность смысловых фактов оценивается отдельно — низкий WER не исключает критическую ошибку отрицания/числа.
- **А, дословность:** фиксировать каждое автоматическое исправление ошибки/удаление повтора как отклонение. Если выбранная модель систематически нормализует речь, исходная гипотеза дословности не подтверждена, даже при приемлемом общем WER.
- **Б, смысл:** ноль изменений существенных утверждений во всех двадцати результатах. Любое добавленное достижение, изменённое число, отрицание или обязательство — критический дефект результата.
- **Б, язык:** ручная оценка по рубрике: грамматическая корректность, естественность, уместность конструкций целевого уровня, сохранение разговорного характера. Каждый пункт оценивается 0–2: не соответствует / частично / соответствует.
- Предлагаемый ориентир Б: минимум 7 из 8 баллов без нулевого пункта хотя бы в 8 из 10 результатов для каждого уровня, при выполнении требования сохранения смысла во всех случаях.
- Оценку выполняет владелец продукта; при спорных B2/C1 желательно привлечь компетентного преподавателя/рецензента. Самооценка той же генерирующей модели не является независимой приёмкой.
- Для каждого запроса фиксировать время, модель, версию инструкции, вход, результат и ошибки в локальном протоколе проверки. Секреты в протокол не включать.

Пороги — предложения для исследовательского этапа, не утверждение достижимой точности. При провале порога сначала определяем причину; смена модели/правил согласовывается, а не выполняется незаметно.

## 13. Подготовка, выполнение и завершение этапа

1. Пользователь согласовывает этот документ или присылает правки.
2. Подготавливаем доступ владельца, секрет OpenRouter и доступность платных моделей; секреты передаются только защищённым способом.
3. Реализуем веб-интерфейс, локальное хранение, контракт/API, две операции и обработку ошибок.
4. Проверяем технические сценарии и выполняем контрольную оценку на смартфоне.
5. Фиксируем результаты, исправляем дефекты и решаем, готова ли гипотеза к MVP.
6. Требования MVP готовим и согласовываем отдельно. Отложенные функции автоматически в реализацию не попадают.

Публикация для общего доступа и расходы на внешние сервисы не запускаются самим согласованием текста: подключение ключа и разрешение на публикацию — отдельные действия.
